Cloud sync

Overview Architecture Data model Extending Run & deploy

Sync is optional and off by default. It backs up the whole app state to a single kinetos.json file in your own cloud drive. Because Kinetos has no backend, it uses the provider's OAuth from the browser and stores tokens only in this browser's localStorage — they are never uploaded.

Currently only Google Drive is enabled. OneDrive and Yandex adapters exist but are switched off via enabled: false in js/config.js — flip them on to use them.

How it works

  • State carries an updatedAt timestamp. Sync pulls the remote file, merges it (union of plans/sessions/exercises by id; last-write-wins on profile/settings), then pushes the result to kinetos.json.
  • Deletions are tracked as tombstones (id + deletion time). The merge unions tombstones and removes any re-appearing id, so deleting a session/template/plan on one device sticks instead of being re-added from another device's copy. An edit newer than the deletion still wins (resurrects). Tombstones self-prune after ~6 months.
  • Triggers: on app open, when you tap Sync now, and automatically every autoEveryMinutes (default 10) if something changed. It also runs a full sync (pull + merge + push — never a blind overwrite) when the tab is hidden and when the network comes back; concurrent triggers coalesce into a single run.
  • Everything still works fully offline; sync simply resumes when you're back online and connected.

Setup (once per provider)

Fill in the clientId for the provider(s) you want in js/config.js. The redirect URI to register is your app's own URL, e.g. https://USER.github.io/REPO/ (or http://localhost:8080/ for local Docker). It must match SYNC.redirectUri exactly.

Google Drive (enabled)

  1. Google Cloud Console → create a project → APIs & Services. Enable the Google Drive API.
  2. Credentials → Create OAuth client ID (type: Web application). Add your redirect URI (e.g. https://USER.github.io/REPO/) as an Authorized redirect URI.
  3. Scope: https://www.googleapis.com/auth/drive.file — the app can only see files it creates. Kinetos creates one file, kinetos.json, in your Drive and remembers its id locally.
  4. Paste the Client ID into providers.google.clientId, and provide the secret one of two ways (below).

The client secret

A "Web application" Google client requires a secret at token exchange. A static app can't truly hide it, so pick your trade-off:

  • Encrypted (recommended for public repos) — open tools/encrypt-secret.html in a browser, enter the secret + a passphrase, and paste the result into providers.google.clientSecretEnc. The app asks for the passphrase once per session (kept in sessionStorage) to unlock it. The passphrase is never stored.
  • Plaintext — put it in providers.google.clientSecret. Simplest, but readable by anyone who can load the deployed JS. Only for private deployments.

If both are set, clientSecret wins. (A PKCE public client with no secret is the most secure option overall, but requires a client type that omits the secret.)

OneDrive / Yandex (disabled)

Set enabled: true for providers.onedrive / providers.yandex in js/config.js and fill in their clientId. OneDrive uses Graph Files.ReadWrite.AppFolder + offline_access; Yandex uses cloud_api:disk.app_folder with the implicit token flow (no secret).

Using it

Profile → Cloud sync → pick a provider → Connect (you're redirected to sign in and come back). After that it syncs automatically; Sync now forces it. Disconnect clears the local tokens. Status and last-synced time are shown there.

Notes & limits

  • A static site can't keep OAuth secrets private — that's why you register your own app. Tokens stay on-device.
  • Conflict handling is intentionally simple (union + last-write-wins + tombstones for deletes). Fine for one person across devices; not a multi-user CRDT.
  • If a provider requires a confidential client (secret), that's not truly secret in a browser app — acceptable only for personal, self-hosted use.
