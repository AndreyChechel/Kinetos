Cloud sync

Overview Architecture Data model Extending Run & deploy

Sync is optional and off by default. It backs up the whole app state to a single kinetos.json file in your own Google Drive. Because Kinetos has no backend, it authorizes from the browser and keeps the access token only in this browser's localStorage — it is never uploaded.

Google Drive is the only provider. Since 1.14.0 authorization uses Google Identity Services (the token model), so there is no client secret anywhere — nothing in this repo is sensitive. Earlier builds used the authorization-code flow, whose token endpoint demands a client_secret; that secret had to be shipped AES-encrypted with a passphrase prompt. All of it (secret.js, tools/encrypt-secret.html, the redirect round-trip) is gone.

How it works

  • State carries an updatedAt timestamp. Sync pulls the remote file, merges it (union of plans/sessions/exercises by id; last-write-wins on profile/settings), then pushes the result to kinetos.json.
  • Deletions are tracked as tombstones (id + deletion time). The merge unions tombstones and removes any re-appearing id, so deleting a session/template/plan on one device sticks instead of being re-added from another device's copy. An edit newer than the deletion still wins (resurrects). Tombstones self-prune after ~6 months.
  • Triggers: on app open, when you tap Sync now, automatically every autoEveryMinutes (default 10) if something changed, when the tab is hidden, and when the network comes back. Always a full sync (pull + merge + push — never a blind overwrite); concurrent triggers coalesce into a single run.
  • Everything still works fully offline; sync resumes when you're back online and authorized.

The one-hour token (why a tap is sometimes needed)

The token model issues an access token that lasts about an hour and no refresh token. A new one has to be requested from a real user gesture, because Google opens a popup and browsers only allow that during a click. So the background triggers above run only while a live token is in hand; they never try to authorize.

When the token has lapsed, Kinetos keeps the data marked dirty, sets the needsAuth status, and asks for one tap: a toast with a Sync action on app open (once per run), plus the button in Profile → Cloud sync. Nothing is lost by deferring — every sync is a full pull+merge+push, so a later one converges identically. Because the grant is already recorded for your account and prompt: '' is set, that tap is a popup flash with no account chooser and no consent screen.

The gesture rule matters in code. Transient user activation is consumed across await, so the GIS library must be loaded before the click (manager.prepareAuth(), called on boot and when the Profile card renders) and requestAccessToken() must be reached synchronously from the handler. See the header comment in js/sync/gis.js.

Setup (once)

  1. Google Cloud Console → create a project → APIs & Services. Enable the Google Drive API.
  2. Credentials → Create OAuth client ID, type Web application.
  3. Under Authorized JavaScript origins add your app's origin — scheme + host + port, no path: e.g. https://USER.github.io and http://localhost:8080 for local Docker. The /REPO/ sub-path does not appear here, unlike the redirect URIs older builds needed. Authorized redirect URIs can be left empty.
  4. Scope: https://www.googleapis.com/auth/drive.file — the app can only see files it creates. Kinetos creates one file, kinetos.json, and remembers its id locally.
  5. Paste the Client ID into providers.google.clientId in js/config.js. That's the whole configuration.
  6. The client secret on that client is unused — rotate or delete it. If you previously published one, this is what retires it.

Keep the same client id when possible: drive.file visibility is tied to the OAuth client that created the file, so a new client id means the app can no longer see a kinetos.json it wrote earlier (recoverable via Profile → export/import JSON, or by letting it create a fresh file).

Using it

Profile → Cloud sync → pick Google Drive → Connect (a Google popup opens; you stay on the page). After that it syncs automatically while the token is live; Sync now forces it, and Sign in to sync appears in its place once the hour is up. Disconnect revokes the grant and clears the local token. Status and last-synced time are shown there.

Notes & limits

  • A static site cannot keep an OAuth secret private, which is why this build has none at all. The client ID is public by design; it authorizes nothing on its own.
  • The GIS library is loaded from Google's CDN at sync time only. It is deliberately not precached in sw.js (cross-origin), so the offline app shell never depends on it.
  • Popups and installed PWAs: the token flow opens a popup, which can behave oddly in display: standalone (notably on iOS). Worth checking on your installed app; the old redirect flow was more forgiving there.
  • Conflict handling is intentionally simple (union + last-write-wins + tombstones for deletes). Fine for one person across devices; not a multi-user CRDT.
  • OneDrive and Yandex adapters were removed in 1.14.0 along with the redirect/PKCE machinery they depended on. Recover them from git history if you want them back.
