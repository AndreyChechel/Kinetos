Add an exercise

  1. Add an object to js/data/exercises.json (see the schema). Pick an existing group and valid primary/secondary muscle keys from js/data/muscles.json.
  2. Generate its illustration: run python tools/generate_svgs.py. It writes assets/exercises/<id>.svg for every exercise from the JSON.
  3. Add the new SVG path to the CORE/precache logic only if needed — sw.js already precaches every id listed in exercises.json automatically, and bump CACHE in sw.js so clients refresh.

Users can also add ad-hoc exercises at runtime (Exercises → + button); those are stored in customExercises and get a runtime-generated muscle-map SVG from their group via js/exsvg.js (no SVG file needed).

Add a language

  1. Copy locales/en.json to locales/<code>.json and translate the values.
  2. Add { code, label } to SUPPORTED in js/i18n.js.
  3. Add the file to CORE in sw.js and bump CACHE.
  4. Optionally add localized names/cues entries in exercises.json; missing languages fall back to English via pick().

The SVG generator

tools/generate_svgs.py (stdlib only) writes an animated SVG per exercise: a side-view (or front/back-view) figure performing the movement in a loop, with the equipment drawn in and the worked muscles highlighted on the body (class="muscle-stroke", secondary muscles at half strength), plus a small front/back muscle-map inset (class="ex-map", hidden in thumbnails). Animation is plain SMIL <animate> on path/circle attributes (one value per sampled frame), so it needs no JS or CSS; frame 0 is also the static state. Body and props use currentColor, so the art follows the theme.

  • tools/poses.py — one entry per exercise: start pose a and end pose b (played a→b→a), or cycle(t) for running/cycling/rowing, or only a for a still hold; plus props, dur, optional zoom. A pose is segment angles in degrees (0 = right, 90 = down; the figure faces right) or IK targets for hands/feet, pinned by at=(joint, (x,y)). An exercise with no entry falls back to a standing figure.
  • tools/figure.py — the rig (FK/IK, foreshortening, views), muscle placement tables and SVG assembly.
  • tools/props.py — equipment primitives (bench, plate, dumbbell, cable, stack, pads…).
  • Preview: python tools/generate_svgs.py --only bench-press --frames /tmp/fr dumps still frames to inspect.

In the app (js/svg.js) only the full-size detail illustration plays; thumbnails and users with prefers-reduced-motion get frame 0 via pauseAnimations(). Custom exercises still use the runtime muscle map from js/exsvg.js.

Calculations (js/calc.js)

FunctionFormula / basis
maxHR(age)Tanaka: 208 − 0.7·age
hrZones(age, restingHR?)5 zones; Karvonen (HR reserve) if resting HR given, else % of max HR
oneRepMax(weight, reps)Epley & Brzycki, averaged
weightForReps(1RM, reps)Inverse Epley — suggested load for a rep target
bmi(weightKg, heightCm)kg / m² (+ WHO category)
bodyFat(w,h,age,sex)Deurenberg estimate from BMI/age/sex
bmr(w,h,age,sex)Mifflin-St Jeor
tdee(...activityLevel)BMR × activity factor (1.2–1.9)

All are estimates for planning, not medical advice. They are pure functions — easy to unit test or swap.

Target suggestions (js/suggest.js)

Lightweight autoregulation. suggestNext(exerciseId, excludeSessionId) finds the last session that trained the exercise (via historyFor, which only counts performed sets — done !== false), takes the reference set (heaviest, then most reps), and combines the average effort rating with whether the target reps were hit: a missed target backs off (hold weight, retry the target reps); beating it pushes up. Otherwise: effort < 1.7 → progress (weighted: +1 step; bodyweight: +2 reps; time: +15 s), 1.7–2.3 → steady (+1 rep), > 2.3 → back off. The weight step is per-equipment (barbell/machine/cable 2.5 kg, dumbbell 2 kg) and can be overridden per exercise on its detail screen (stored in exerciseMeta[id].weightStep). With no signals it defaults to steady. Surfaced as a chip in the active session (with a Use button and auto-prefill of new sets) and as a "Suggested next" card on the exercise detail. Tune the thresholds/increments at the top of suggest.js.

Add a screen

  1. Create js/views/whatever.js exporting a render function (root, params, ctx).
  2. Import it in app.js and add a route to the table in routes().
  3. Add a tab in index.html (.tabbar) with data-tab, or link to it from an existing view.
  4. Add its file to CORE in sw.js; bump CACHE.
