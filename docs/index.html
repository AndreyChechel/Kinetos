Kinetos — project context

Offline-first PWA to plan and track gym workouts. Vanilla JS (ES modules), no build step, no backend, data in localStorage. These docs are written to give a future session enough context to continue work quickly.

Architecture Data model Extending Run & deploy

What it does

  • Exercises — ~38 built-in exercises grouped by muscle group, each with an inline SVG "muscle map" illustration and how-to cues. Users can add custom exercises.
  • Plan — create planned sessions (name, date, exercises with target sets/reps/weight).
  • Session logging — start a session (empty or from a plan), log sets with weight/reps/time/distance; each completed set records a timestamp for timing analysis; live elapsed timer.
  • Progress — week stats, volume over time, sets by muscle group, estimated 1RM trend, recent sessions. Uses Chart.js if present, else a built-in fallback.
  • Profile — name, photo, sex, birthdate, height, weight, resting HR, activity level; auto-calculated metrics: max HR + HR zones, BMI + body-fat, BMR + TDEE, 1RM. JSON export/import + reset.
  • Cross-cutting — 5 languages (EN/DE/FR/ES/RU), light/dark themes, installable, fully offline via a service worker.

Key decisions

  • No framework, no bundler — plain ES modules loaded by index.html. Easiest to reason about and to serve statically.
  • All paths are relative so the app runs unchanged at a domain root or under a GitHub Pages subpath (/repo/).
  • Single source of truth for exercises: js/data/exercises.json — the app and the SVG generator both read it.
  • Units are metric (kg/cm). Calculations are estimates only (see Extending).
