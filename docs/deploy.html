Run locally

run.bat (in the project root) runs docker compose up -d and opens http://localhost:8080 in the default browser. It checks that Docker is installed and running first.

docker-compose.yml mounts the project into an nginx:alpine container read-only and applies nginx.conf, which:

  • serves *.webmanifest with the correct MIME type;
  • marks sw.js and index.html no-cache so updates roll out;
  • falls back to index.html for deep links.

Stop it with docker compose down. No Docker? Any static server works, e.g. python -m http.server 8080 from the project root.

Offline libraries

tools/download-vendor.bat downloads Chart.js into vendor/chart.umd.js (via curl). The Progress screen loads it if present and otherwise uses a built-in fallback chart, so the app never hard-depends on it.

PWA / offline

  • manifest.webmanifest — installable metadata; icons in assets/icons/; start_url/scope are relative.
  • sw.js — precaches the app shell, all locales and every exercise SVG on install; runtime cache-first for everything else same-origin; navigations fall back to the cached shell. Bump CACHE when app files change.
  • Install prompt is captured in pwa.js; the Profile screen shows an "Install app" button when available.

Publish to GitHub Pages

  1. Create an empty GitHub repo.
  2. Edit tools/publish.bat → set REPO_URL (and BRANCH, default gh-pages).
  3. Run tools/publish.bat. It initialises git if needed, copies the site into a temporary gh-pages worktree (excluding .git, node_modules, *.bat), adds .nojekyll, and force-pushes to the branch.
  4. In the repo: Settings → Pages → source = gh-pages branch, folder / (root).

Because all paths are relative, the app works at https://USER.github.io/REPO/ without changes. Commit the vendor/ file too if you want charts to work offline on the hosted version.
