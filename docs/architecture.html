Boot flow

index.html loads js/app.js as a module. app.js:

  1. applies theme (applyTheme(), reads settings.theme + system preference);
  2. await initI18n(settings.lang) and await loadDB() (fetch exercise + muscle JSON);
  3. defines routes and starts the router (History API, clean URLs);
  4. initPWA() registers the service worker and captures the install prompt.

Rendering model

No virtual DOM. A route handler calls show(renderFn, meta, params) in app.js, which clears the #view element, sets the active tab / title / back button, then calls renderFn(viewEl, params, ctx). Views build DOM with the h() helper and attach listeners directly. State mutations go through store.js and are persisted immediately; views re-render by re-running the current route (e.g. ctx.navigate()) or by rebuilding a sub-section in place.

ctx passed to views: { setTitle, setActions, navigate }.

Responsive layout

Mobile-first. On phones the nav is a fixed bottom tab bar and content is a single centered column. At min-width: 900px the same .tabbar becomes a left sidebar rail (the .tabbar__brand element, hidden on mobile, shows here), content widens, and .grid2 tile rows expand via auto-fit. The exercise detail becomes two columns (.ex-detail: sticky illustration + info). All purely CSS in css/styles.css; show() in app.js tags the view element with view--<tab> for per-screen styling. Hover affordances are gated behind @media (hover:hover).

Illustrations

Exercise SVGs are fetched and injected inline (not <img>) so they use currentColor for the body and the .muscle-fill class (themed accent) for the targeted muscles. Fallback emoji shows if an SVG is missing (e.g. custom exercises).
